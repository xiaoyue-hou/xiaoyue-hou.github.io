2024-A Large-scale Benchmark Dataset for Commuting Origin-destination Matrix Generation

通勤 OD矩阵 图生成
Paper
发布日期:   2026-10-25

一个模型懂大城市的通勤，就能补出小县的通勤吗？

假设你需要画出一个县的通勤联系，但手里只有人口、设施与地理边界。用大城市训练出的模型也许会把人流集中到一个中心；目标县却可能有几处分开的就业聚集区。模型缺的不只是更多记录，而是更多结构不一样的地方。这篇论文把训练样本从少数城市扩展到 3,233 个美国区域，再比较逐对估计流量和生成整张网络有什么不同。

论文名片：Can Rong、Jingtao Ding、Yan Liu、Yong Li，A Large-scale Benchmark Dataset for Commuting Origin-destination Matrix Generation，2024 年 7 月 24 日 arXiv:2407.15823v3。本文采用与配图对应的作者预印本 v3；2025 年 ICLR 正式稿另有题名和样本数量，文末单独列出。

3,233 个区域里，每一格流量是什么？

以县界构成每个研究区域，以人口普查区作内部单元。对一个含 N 个普查区的县，通勤起讫（OD）矩阵就有 N 行、N 列。第 i 行、第 j 列记录住在 i 区、在 j 区工作的人数。矩阵来自 2018 年 LODES 居住地—就业地统计；它不是逐日刷卡、GPS 观测或实际走过的路段。矩阵只统计研究区内部的联系，跨县通勤不能直接从县内矩阵补出来。

模型还拿到美国社区调查的 97 维人口社会经济特征，以及 OpenStreetMap 的 36 类兴趣点计数。距离按普查区形心计算，不能等同于路网距离或通勤时间。这些条件可以在没有目标县历史流量时提供线索，但不等于这个县没有任何数据要求。

图 1｜上半部从少数地区训练后直接迁移，下半部先在不同类型区域学习。箭头展示研究设计，不是任意两座城市间无法迁移的实验证据。来源：arXiv v3 图 1。

图 2｜（a）读内部普查区个数，（b）读区域平均出行距离，（c）读流量差异的方差。三个横轴的单位和含义各不相同。来源：arXiv v3 图 2。

同样规模的县也未必长得一样。Maricopa 的连线较集中，Alameda 由多个聚集点组织，Contra Costa 的联系则相对分散。论文用这些区域作为单中心、多中心与较平滑结构的例子，不是说所有通勤只遵循其中一种形状。

图 3｜（a–c）依次是 Maricopa、Alameda、Contra Costa。线是起讫联系的可视化，不是实际通勤路线。来源：arXiv v3 图 3。

图 4｜（a）按普查区数量分组比较 OD 流量分布；（b）横轴标注为流出量，不宜按图题里的 Node degrees 读成非零边条数。来源：arXiv v3 图 4。

为什么整张网络一起生成？

若逐格预测，模型会分别回答「i 到 j 有多少人」。整图生成还会利用同一网络中的关系：多个住宅区可能共享就业中心，同一住宅区也会把流出分到不同终点。作者把普查区作为节点，人口与设施作为节点属性，居住—工作人数作为有向边权。这里的一条边就是 OD 矩阵中的一个数，并不显示个人。

图 5｜左侧属性表与 OD 表，对应右侧五个节点、箭头和边上的数值。生成的是边权，不是节点人口与设施。来源：arXiv v3 图 5。

WeDAN 在训练时给整张已知矩阵加噪，再学习如何在区域信息引导下反向去噪。到目标县生成时，从噪声矩阵开始，给定当地的节点属性、距离等条件，逐步得到通勤流量。这个过程不使用目标县的历史 OD 作为输入，但训练仍用其他地区的真实统计矩阵。扩散的阶段也不是现实中的时间步，不能用它模拟明早到明晚的流量变化。

图 6｜右至左看训练时加噪，左至右看生成时去噪。各状态是同一张矩阵在算法中的版本。来源：arXiv v3 图 6。

图 9｜附录框架展示节点与带噪边分别编码，距离信息一起进入图 Transformer，最后输出边级噪声估计。学到的权重不是被验证过的个人通勤原因。来源：arXiv v3 附录图 9。

CPC 0.593 到底说明了什么？

研究按区域做 8:1:1 划分，重复试验后报告区域平均表现。首先看共同通勤部分 CPC：把每对起讫点在生成与参照矩阵中的较小流量加起来，再除以两张矩阵总量的平均值。完全重合为 1，毫无重合为 0。它不需要逐人对照，因此也是流量重叠，不是“59.3% 的人被猜对了目的地”。RMSE 则衡量逐格流量误差，对较大的绝对偏差更敏感。

v3 表 2 的部分结果 CPC ↑ RMSE ↓ 流入分布偏差 ↓ 流出分布偏差 ↓
幂律引力模型 0.321 174.0 0.668 0.656
随机森林 0.458 100.4 0.424 0.503
DiffODGen 0.532 74.6 0.324 0.270
WeDAN 0.593 68.6 0.291 0.269

从 0.532 到 0.593 是 CPC 增加 0.061，相对增加约 11.5%；RMSE 则降低约 8.0%。流出分布偏差只小幅下降。不同指标回答不同问题：一个模型可以较好复现各普查区流出规模，但仍把流量分给了错误的就业区。附录中 WeDAN 和 DiffODGen 都依赖多次生成后取平均，因此这些比较也不能当作每次独立生成的保证。

换一种县型，平均数还靠得住吗？

作者先按普查区数量和中心结构分别拆开结果，再做四种跨类型实验：单中心训练、多中心测试以及反方向，大区域训练、小区域测试以及反方向。随着源区域训练样本增加，目标组的 CPC 大体提高，但与全类型训练基准仍有差距。这支持不同地方有可学习的通勤共性，也说明数据类型覆盖本身仍然重要。

图 7｜（a、b）按普查区数量分组，（c、d）按中心结构分组；CPC 越大越好，RMSE 越小越好，不能只看雷达图面积。来源：arXiv v3 图 7。

图 8｜（a、b）为跨中心结构，（c、d）为跨规模；横轴是训练区域数，黑色虚线是使用全部类型训练的参照。来源：arXiv v3 图 8。

这些都是同一国家、同一统计体系、2018 年就业数据下的划分。它们没有单独验证疫情后办公方式、其他国家或道路重建后的变化。即使县内 OD 生成很好，也不能直接得到线路客流或道路拥堵；还需要路网、方式选择和跨县联系等独立测量与验证。

研究结论

  • 预印本 v3 以 3,233 个美国区域、县内普查区和 2018 年 LODES 为统一口径，为通勤矩阵生成提供了可比较的基准。
  • 在这套实验中，WeDAN 的整体 CPC 和 RMSE 好于表中最佳对照 DiffODGen，幅度须按各指标分别读。跨类型试验则表明多样化样本仍有价值。
  • 没有目标地历史 OD，不等于没有数据依赖；生成的矩阵既非逐人移动，也不能替代跨边界和实际交通服务的评估。

核心总结

这篇预印本的主要贡献不只是一个得分更高的扩散模型，还把都会、小城和乡村等不同环境放进一套共同的通勤评测。WeDAN 用地区属性引导整张居住—就业网络生成，结果显示联合建模有潜力，也说明训练覆盖不足时，目标地的网络结构仍不好学。把结果用于实际规划前，需要先确认当地边界、年份和指标口径，再检验所关心的通勤联系，而不是只看全国平均分。

延伸思考

以下是 AI 基于论文结果所作的延伸，不属于原论文结论。

假设某县希望用生成的 OD 帮助调整班车。整体 CPC 较高，不保证模型对县里唯一一家大型医院的工作人员来源估得准。更贴近实际的做法，是在比较总体流量重叠之外，先圈定服务要覆盖的几个就业中心，再用独立的、汇总后的站点或岗位数据核对它们的主要来源。若两套模型平均分相近，可以优先选在这些联系上误差更小的一套。
